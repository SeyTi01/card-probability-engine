# GitHub writing

Lead with the concrete problem and resulting or intended behavior. Describe the final scope, relevant contracts and unresolved choices; link prerequisites and issues. Avoid conversational history.

Omit routine tests, CI and privacy-check inventories from issues, PRs and comments. Include blockers and consequential evidence such as measured regressions or release artifact identity. Keep routine verification results in the task conversation.

Use structured body arguments or exact UTF-8 `--body-file` input. Check public text/images for private identities, machine paths and unrelated information; use the established public project identity. Verify the written result and return its link.
